A system requirement that no single module can meet alone is split into budgets, one for each module on the path. Each budget is a requirement on that module, so a module team can design and verify against its own specification, and a change to one budget is visible to the others.

Five system requirements are split this way. Each split is a derivation in the model that records why the budgets close. The module requirements constrain design values that are attributes of the module in the model, so the model shows at any time whether the current design is inside its budget.
